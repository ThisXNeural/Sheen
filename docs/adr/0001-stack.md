# ADR 0001 — انتخاب استک: Rust + Tauri v2 + Svelte 5

- وضعیت: پذیرفته‌شده
- تاریخ: 2026-11-05

## زمینه

چهار گزینه بررسی شد: Tauri v2، C# + WinUI 3، Rust + Slint، و C++ با DirectComposition.
سؤال اصلی این بود که برای Sheen کدام مهم‌تر است: **کیفیت و راحتی انیمیشن** یا **سبکی افراطی منابع**.

## تصمیم

اولویت با **کیفیت حس و انیمیشن** است. انتخاب: **Rust + Tauri v2 + Svelte 5**،
با یک شرط معماری: منطق برنامه در یک crate مستقل از UI (`sheen-core`) نوشته شود.

### چرا

1. **ارزش محصول در «حس» آن است.** Dynamic Island یعنی morph کشسان بین حالت‌ها.
   فنر (`svelte/motion` Spring)، blur تصویر آلبوم، crossfade محتوا و تایپوگرافی
   در وب چند خط کد است. همین کارها در Slint یا DirectComposition کار رندرر دستی می‌خواهد.
2. **دسترسی به API ویندوز چیزی کم ندارد.** کل بک‌اند (SMTC، Core Audio، Win32) با
   `windows-rs` نوشته شده است، یعنی همان دسترسی نیتیو گزینه‌های ۳ و ۴.
3. **ریسک WinUI 3 دقیقاً در هسته‌ی پروژه است.** پنجره‌ی بی‌فوکوس، شفاف و click-through
   کاری است که WinUI 3 با آن درگیر است و Tauri مستقیم پشتیبانی می‌کند
   (`focusable: false`، `set_ignore_cursor_events`).
4. **راه فرار باز است.** UI فقط یک `Presentation` (JSON) را رندر می‌کند. اگر روزی مصرف رم
   تبدیل به مشکل شد، می‌شود `ui/` + `src-tauri/` را با یک فرانت Slint عوض کرد بدون
   اینکه `sheen-core` و `sheen-win` تغییر کنند.

### هزینه‌ای که پذیرفتیم

- مصرف رم حدود ۵۰ تا ۷۰ مگابایت به‌خاطر WebView2. هدف فاز ۱: اندازه‌گیری روی سخت‌افزار واقعی.
- وابستگی به WebView2 runtime. روی ویندوز ۱۱ از قبل نصب است و installer در صورت نیاز آن را نصب می‌کند.

## تصمیم‌های فنی ناشی از آن

| مسئله | راه‌حل |
|---|---|
| لرزش هنگام resize پنجره همگام با CSS | پنجره‌ی ثابت و شفاف 640×280. کپسول **داخل** آن انیمیت می‌شود و پنجره هیچ‌وقت resize نمی‌شود. |
| `HTTRANSPARENT` با WebView2 کار نمی‌کند (ورودی به child HWND می‌رود) | toggle کردن `WS_EX_TRANSPARENT` بر اساس موقعیت کرسر. ناحیه‌ی کلیک از `sheen-core` می‌آید و در طول انیمیشن، اجتماع شکل قبلی و جدید است. |
| `backdrop-filter` در وب‌ویو دسکتاپ پشت پنجره را blur نمی‌کند | کپسول **مشکی مات** است (مثل آیلند اپل). blur فقط روی کاور آلبوم داخل کارت اعمال می‌شود. |
| ربودن فوکوس | `WS_EX_NOACTIVATE` + `focusable: false`. اسکرچ‌پد (فاز ۳) فوکوس را آگاهانه می‌گیرد و بعد پس می‌دهد. |
| ارسال پیوسته‌ی موقعیت ترک روی IPC | فقط snapshot و زمان نمونه‌برداری ارسال می‌شود و UI خودش interpolate می‌کند. |

## ریسک‌هایی که باید روی ویندوز واقعی تأیید شوند

- اینکه کلیک روی WebView2 با `WS_EX_NOACTIVATE` واقعاً پنجره‌ی قبلی را deactivate نکند.
  اگر کرد، باید `WM_MOUSEACTIVATE` را با subclass کردن پنجره پاسخ `MA_NOACTIVATE` بدهیم.
- مخفی کردن فلای‌اوت ولوم خود ویندوز API رسمی ندارد.
- سوییچ خروجی صدا به `IPolicyConfig` نیاز دارد که مستندسازی نشده است.

## افزوده: پلیر داخلی و تم (2026-11-05)

- **پخش در Rust است، نه در وب‌ویو.** پخش با rodio روی یک thread جدا انجام می‌شود، پس بسته بودن پنجره‌ی اصلی روی آن اثری ندارد.
  دستگاه صوتی فقط هنگام پخش باز است و بعد از ۳۰ ثانیه توقف آزاد می‌شود.
- **پلیر داخلی خودش را در SMTC ثبت می‌کند.** آیلند آن را از همان مسیری نشان می‌دهد که Spotify را نشان می‌دهد
  و کلیدهای مدیا بدون کد اضافه کار می‌کنند.
- **پنجره‌ی اصلی lazy است.** فقط وقتی باز می‌شود ساخته می‌شود و با بستنش WebView آن از بین می‌رود.
  آیلند و پنجره‌ی اصلی دو entry جدای Vite دارند تا باندل آیلند کوچک بماند.
- **تم:** WebView2 تم ویندوز را از طریق `prefers-color-scheme` گزارش می‌دهد و با تغییر آن event می‌فرستد.
  حالت «System» همین را دنبال می‌کند و Light و Dark آن را override می‌کنند. انتخاب در `settings.json` ذخیره می‌شود
  و با `app.set_theme` روی همه‌ی پنجره‌ها اعمال می‌شود.

## افزوده ۲: انتقال‌ها، قفسه، نوت و تست UI

- **دانلودها و کپی فایل.** ویندوز API عمومی برای خواندن پیشرفت برنامه‌های دیگر ندارد، پس هر منبع از همان راهی خوانده می‌شود که خودش در اختیار می‌گذارد:
  - **مرورگرهای Chromium:** اندازه‌ی فایل `.crdownload`، و حجم کل از دیتابیس History. دیتابیس با `winsqlite3.dll` خود ویندوز و در حالت `immutable` خوانده می‌شود: بدون کپی فایل و بدون قفل.
  - **Firefox:** فقط اندازه‌ی فایل `.part`، پس سرعت و حجم دانلودشده نشان داده می‌شود ولی زمان باقی‌مانده نه.
  - **دیالوگ کپی File Explorer:** از طریق UI Automation.
  - **دیالوگ‌های Win32** (IDM، 7-Zip، WinRAR، نصب‌کننده‌ها): با پیام `PBM_GETPOS`.
- **زمان باقی‌مانده.** فیلتر کالمن روی سرعت، ترکیب با میانگین کل، و یک لایه‌ی نمایش که عدد را نرم شمارش معکوس می‌کند و هیچ‌وقت ناگهان نمی‌پرد. با تست‌های واحد برای نویز، توقف و تغییر سرعت.
- **قفسه.** شروع درگ فایل از روی پنجره‌ی `SysDragImage` شل تشخیص داده می‌شود. بیرون کشیدن فایل‌ها با `SHDoDragDrop` خود ویندوز انجام می‌شود، پس رفتارش دقیقاً مثل درگ از Explorer است.
- **نوت.** یک پنجره‌ی جدا (و نه خود آیلند)، چون آیلند عمداً فوکوس نمی‌گیرد و برای تایپ به فوکوس نیاز است. پنجره در اولین استفاده ساخته می‌شود و بعد فقط پنهان می‌شود.
- **کاور آلبوم‌ها.** با پروتکل `sheen-art://` به `<img>` می‌رسند: یک بار کوچک می‌شوند، روی دیسک کش می‌شوند، lazy بارگذاری می‌شوند و هیچ‌وقت به شکل base64 از IPC عبور نمی‌کنند.
- **تست UI.** تست سرتاسری Playwright هر صفحه، هر حالت آیلند، دو تم، سه اندازه‌ی پنجره و متن‌های بلند و فارسی را با بررسی هندسی چک می‌کند: بیرون‌زدگی، هم‌پوشانی و متن بریده‌شده. برای خود بررسی‌کننده هم تست نوشته شده تا مطمئن شویم این مشکلات را واقعاً پیدا می‌کند.
